# Dotinout employee app (Flutter)

Replaces the Capacitor employee app. Talks to the existing Next.js `/api` routes (see `../API-INVENTORY.md`).

## First-time setup (once Flutter is installed)

The native `android/` and `ios/` folders are generated by Flutter, so run this once from the repo root:

    flutter create --org com.dotinout --project-name dotinout_employee --platforms=android,ios employee_app

Then keep the `lib/`, `test/`, `pubspec.yaml` and `analysis_options.yaml` in this folder (they overwrite the generated
starter files). Keep the same bundle ID as the Capacitor app, `com.dotinout.app`, so the store listing is updated and not
replaced: set `applicationId` in `android/app/build.gradle` and `PRODUCT_BUNDLE_IDENTIFIER` in the iOS Runner target.
Copy `../ios/App/App/PrivacyInfo.xcprivacy` into `ios/Runner/` and add it to the Runner target's Copy Bundle Resources.

## Configuration

No `.env` file is bundled. The API address is passed at build time:

    flutter run --dart-define=API_BASE_URL=https://your-domain.example

Use the same production domain as the web app. Release builds must use https.

## Checks

    flutter pub get
    flutter analyze
    flutter test

## What is in M1

- Sign-in against `POST /api/mobile/auth/login` (employees only). The token is kept in secure storage.
- Session restore on launch (`GET /api/auth/me`). An expired token returns the user to sign-in.
- Sign-out (`POST /api/auth/logout`), which revokes the session on the server.
- Bottom navigation with the four tabs (Home, Attendance, Leaves, Salary) and More. Tab screens are placeholders until M2.
- Friendly error messages. Network failures never show raw browser or socket errors.
