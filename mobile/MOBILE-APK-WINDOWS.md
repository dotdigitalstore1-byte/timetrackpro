# Dotinout Android APK build (Windows, no EAS)

This project uses React Native with Expo SDK 54. You do **not** need Expo Go or an Expo/EAS account to build an installable debug APK. Expo Prebuild generates the native Android project; Gradle builds it locally.

## A. One-time Windows setup

1. Install **Node.js 22 LTS**: https://nodejs.org/
2. Install **Android Studio**: https://developer.android.com/studio
3. In Android Studio > More Actions > SDK Manager, install:
   - Android SDK Platform (the version required by the Expo SDK 54 generated project; install the latest stable platform offered if unsure)
   - Android SDK Build-Tools
   - Android SDK Platform-Tools
   - Android SDK Command-line Tools (latest)
4. In Android Studio > Settings > Languages & Frameworks > Android SDK, note the SDK location. The default is usually `%LOCALAPPDATA%\Android\Sdk`.
5. Set Windows environment variables:
   - `ANDROID_HOME` = your Android SDK folder (usually `%LOCALAPPDATA%\Android\Sdk`)
   - Add `%ANDROID_HOME%\platform-tools` to `Path`
6. Install JDK 17 (Temurin is a suitable free distribution: https://adoptium.net/temurin/releases/?version=17) and set `JAVA_HOME` to its installation folder. Add `%JAVA_HOME%\bin` to `Path`.
7. Close and reopen Command Prompt/PowerShell. Check:

   ```powershell
   node --version
   java -version
   adb version
   ```

   Node should report v22.x and Java should report 17.x.

## B. Build locally

1. Extract the ZIP.
2. Open the extracted `mobile` folder (the folder containing `package.json`).
3. Double-click `build-apk.bat`, or run it from Command Prompt:

   ```bat
   build-apk.bat
   ```

4. The script installs npm packages if needed, runs Expo Prebuild for Android, then runs Gradle `assembleDebug`.
5. On success, the APK is copied to:

   `mobile\dotinout-debug.apk`

   The original Gradle output is:

   `mobile\android\app\build\outputs\apk\debug\app-debug.apk`

If you change native app configuration or native dependencies later, run the build script again. Do not delete the generated `android` folder unless you intend to regenerate it. If you intentionally need a completely fresh native project, back up any manual native Android changes first, then run `npx expo prebuild --platform android --clean` from `mobile` and rebuild.

## C. Install and test on an Android phone

1. Enable Developer options and USB debugging on the phone, or copy the APK to the phone.
2. With USB connected, accept the debugging prompt and run:

   ```bat
   adb devices
   adb install -r dotinout-debug.apk
   ```

   Or open the APK on the phone and allow installation from that source.
3. The app package is `com.dotinout.app`.

## D. GitHub Actions build (no Expo token / no EAS)

1. Push the extracted project to a GitHub repository, keeping the `.github/workflows/mobile-build.yml` file at the repository root.
2. On GitHub, open **Actions** > **Dotinout Android APK (Gradle)**.
3. Choose **Run workflow** > branch > **Run workflow**.
4. Open the completed workflow run. Download the `dotinout-debug-apk` artifact.
5. Extract the downloaded artifact ZIP to get `app-debug.apk`.

The workflow uses GitHub-hosted Ubuntu, Node 22, Java 17, Android SDK and Gradle. It does not use `EXPO_TOKEN`, EAS CLI, or Expo's build servers. GitHub Actions usage is subject to the free plan's included minutes/storage and repository visibility/plan rules; it is not an unlimited hosted build service.

## E. API endpoint

The mobile app defaults to `https://timetrackpro-ai.vercel.app` in `mobile/src/config.ts`. Both local and GitHub builds explicitly set `EXPO_PUBLIC_API_BASE_URL` to that same endpoint. Change it in the build script/workflow if you later use another backend.

## F. Important project notes

- This is still an Expo-managed React Native project using native Android output generated by Prebuild. Expo Go is not used for APK builds.
- The project contains a local Expo native module at `mobile/modules/device-security`; Prebuild/autolinking is expected to include it. If Android build reports that this module cannot be found, inspect Expo autolinking output before changing/removing the module.
- `mobile/README.md` says punch-in/out, leave requests, notice period requests and salary-slip requests are not in this app version. Building an APK does not implement those features; it only packages the current app code.
- `assembleDebug` creates a debug APK for testing, not a Play Store release. For public distribution, create a properly signed release build and securely keep its signing keystore.
